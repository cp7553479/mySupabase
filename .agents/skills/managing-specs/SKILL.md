# Managing Specs

Read the project instructions to identify the requirements document and its conventions.

## Create

1. Gather the confirmed product scope, users, workflows, constraints, and acceptance criteria.
2. Create a concise Markdown requirements document with clear headings.
3. Mark unconfirmed items as open questions; do not present them as decisions.

## Update

1. Read the current requirements document before changing it.
2. Write the requested requirement change into the document first.
3. Present the changed scope for user confirmation.
4. Do not begin implementation until the user confirms the updated requirements.

## Review

Identify missing scope, conflicts, or ambiguous acceptance criteria. Ask only for the smallest decision needed to resolve them.
